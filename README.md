# RegOps

A lightweight GitOps agent written in Rust and built on top of the `regent-sdk` crate, designed for automated and reliable local configuration management.

## Features

* **Decentralized Configuration Management:** Hosts independently manage and enforce their own configurations, combining autonomous local execution with the control, version history, and auditability of a central Git repository.
* **System Service Native:** Full systemd integration for seamless background execution, enabling easy startup, shutdown, and persistence (`systemctl start regops`).
* **Standardized Logging:** Automatic log capture via systemd (`journalctl -u regops`), removing the need for manual file management.
* **Self-Update:** Optional auto-update from GitHub releases. When enabled, the agent periodically checks for new releases, downloads the appropriate package (.deb or .rpm), installs it, and restarts automatically.

## The reconciliation loop (dead simple)

```mermaid
graph TD
    Start([Start Agent Loop]) --> Pull[Pull Expected State YAML from Remote Git Repo]
    Pull --> Apply[Assess or Enforce Expected Configuration to Localhost]
    Apply --> Sleep[Sleep for X Seconds]
    Sleep --> Start
```
## The CLI

### Running the Service

```bash
# Run the RegOps service permanently
regops run

# or just once
regops run-once
```

### Configuration Management

```bash
# Get current configuration
regops config get

# Initialize a new configuration file
regops config init \
  --repo https://github.com/your-org/your-repo.git \
  --branch main \
  --local-path /home/regops/repo \
  --expected-state-path expected_state.yaml \
  --mode enforce \
  --interval-sec 60 \
  --log-level info \
  --log-format raw

# Validate configuration file
regops config validate
```

### Self-Update (Auto-Update)

RegOps can update itself from GitHub releases. Enable it in the configuration file:

```toml
[Behavior]
mode = "Assess"
interval_sec = 30
auto_update = true

[AutoUpdate]
github_api_url = "https://api.github.com/repos/regent-project/regops/releases/latest"
check_interval_sec = 3600
package_format = "Auto"   # Auto, Deb, or Rpm
```

Or via the CLI:

```bash
regops config init \
  --repo https://github.com/your-org/your-repo.git \
  --auto-update \
  --github-api-url "https://api.github.com/repos/regent-project/regops/releases/latest" \
  --auto-update-check-interval-sec 3600 \
  --package-format auto
```

When `auto_update` is `true`, an `[AutoUpdate]` section is required. The agent checks the GitHub API at the configured interval, compares the latest release tag with its own version, and if a newer version exists, downloads the matching package asset and installs it via `dpkg` or `rpm` (using the service's sudo privileges). The process then exits and systemd restarts it on the new binary.

`auto_update` defaults to `false` when omitted, so existing configurations are unaffected.


### Reporting to regency

By default RegOps is standalone: outcomes are only logged. To report every pass to
[regency](https://github.com/regent-project)'s endpoint, set the top-level
`Reporting` key (before the first `[Section]` of the file) and add a `[Regency]`
section:

```toml
Reporting = "Regency"

[Regency]
endpoint = "https://regency.example.com:8443"
ca_cert_path = "/etc/regops/regency-ca.pem"   # CA of the endpoint's server certificate
# host_id = "web-01"         # default: hostname; must equal the host's id in regency inventories
tls_mode = "ExternalCa"      # ExternalCa | BuiltInCa | SelfSigned
```

Each pass runs the expected state as a regent-sdk `RegentTask`, so the outcome is
the same `RegentTaskResult` regency's runners produce. It is written to an on-disk
spool (`/var/lib/regops/spool` by default) and pushed over gRPC/mTLS by a separate
task: the compliance loop never waits for the network, and an outcome is deleted
only once the endpoint accepted it (retried with the same idempotency key).
Outcomes the endpoint refuses for good go to `spool/rejected/`.

Live view: while a pass runs, RegOps streams what it does (attributes, commands and
their output, secrets redacted) to the endpoint (`live = true`, default), so regency
shows it as it happens. This is best effort: nothing is retried, and the pass never
waits for it. The log of the pass (up to `run_log_max_bytes`, 1 MiB by default) is
sent with its outcome, through the spool, for regency's history.

Client certificate (`tls_mode`):

- `ExternalCa` (default): issued by your PKI; set `cert_path` / `key_path`.
- `BuiltInCa`: put the enrollment token generated by a regency admin in the file
  named by `enrollment_token_path`; RegOps obtains its certificate once, then renews
  it automatically (`renew_before_sec`).
- `SelfSigned`: RegOps generates its certificate and logs its SHA-256 fingerprint;
  approve it in regency.

The host id must be a valid DNS name (it is the certificate's subject alternative
name). See [default_config/config.toml](default_config/config.toml) for every key.
