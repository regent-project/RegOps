# Release v0.15.0

## What's Changed

### Windows

- RegOps builds and runs on Windows, as the Windows service `regops`,
  installed by the new MSI package (`regops-<version>-x86_64.msi`; runs as
  LocalSystem, restarted on failure).
- Configuration and state live under `C:\ProgramData\regops\` (`config.toml`,
  `spool`, the `regency` client identity). `default_config/config.windows.toml`
  is installed as the initial configuration and never overwritten by
  upgrades.
- Self-update on Windows: `PackageFormat = "Msi"` (or the default `Auto`)
  downloads the release's `.msi` and installs it with `msiexec`.
- Windows hosts get regent-sdk's Windows support (`windows` feature): the host
  lock (on a lock file) and the attributes that work on Windows.

### Other changes

- Updated following latest regent-sdk update (v0.23.1). The SSHOQ client
  crate is now `sshoq` 0.1.3 (renamed from `shhoq`).
- New release workflow `release-msi.yml` (cargo-wix), next to the deb and rpm
  ones.

### Upgrade notes

- Linux: nothing to do; configuration, paths and packages are unchanged.

# Release v0.14.0

## What's Changed

### Reporting to regency (optional)

RegOps can now push the outcome of every compliance pass to
[regency](https://github.com/regent-project)'s endpoint. Standalone use is
unchanged and remains the default.

- New top-level `Reporting` key: `"None"` (default, outcomes are only logged)
  or `"Regency"`. It must come before the first `[Section]` of the file.
- New `[Regency]` section: `endpoint` (https URL), `ca_cert_path`, optional
  `server_name` and `host_id` (default: hostname; must equal the host's id in
  regency inventories and be a valid DNS name), `tls_mode`, certificate/key
  paths, spool and retry settings. Every key is documented in
  `default_config/config.toml`.
- Delivery: each outcome is written to an on-disk spool
  (`/var/lib/regops/spool` by default) and sent over gRPC with mTLS by a
  separate task, so the compliance loop never waits for the network. An outcome
  is deleted only once the endpoint accepted it; until then it is retried with
  the same idempotency key, across restarts. The spool is bounded
  (`spool_max_entries`, oldest dropped first); outcomes the endpoint refuses for
  good are moved to `spool/rejected/`.
- Client certificate (`tls_mode`):
  - `ExternalCa` (default): issued by your own PKI (`cert_path`, `key_path`);
  - `BuiltInCa`: obtained once from regency's built-in CA with an enrollment
    token (`enrollment_token_path`), then renewed automatically before expiry
    (`renew_before_sec`);
  - `SelfSigned`: generated by RegOps, which logs its SHA-256 fingerprint for
    approval in regency.
- `regops run-once` also records its outcome and tries to send it right away
  (what cannot be sent stays spooled for the service).

### Host lock

- RegOps now takes regent-sdk's host lock, so it never assesses or enforces at
  the same time as a remote Regent runner remediating the same host
  (assessments still run in parallel). Configurable in a new optional
  `[HostLock]` section (`enabled`, `path`, `shared_timeout_sec`,
  `exclusive_timeout_sec`); a busy host skips the pass (logged at info level).

### Other changes

- Each pass now runs as a regent-sdk `RegentTask`, producing the same outcome
  format as regency's runners: a busy host or a failed connection to localhost
  is reported as an outcome of the pass, instead of restarting the service loop.
- Updated following latest regent-sdk update (v0.21.0).
- systemd unit: `StateDirectory=regops`, so `/var/lib/regops` (spool,
  RegOps-managed TLS material) exists and belongs to the service user.

### Upgrade notes

- Existing configuration files keep working: without a `Reporting` key, RegOps
  stays standalone; without `[HostLock]`, the lock is enabled with regent-sdk's
  defaults (`/dev/shm/regent.lock`).
- Building from source now requires `protoc` **36.1** exactly (on `PATH`, or
  set `PROTOC`), needed by regent-sdk's `grpc` feature. Prebuilt packages are
  unaffected.

## Installation

### Debian/Ubuntu
```bash
sudo dpkg -i ./regops_<version>_amd64.deb
```

### RHEL/CentOS/Fedora
```bash
sudo rpm -i ./regops-<version>.<arch>.rpm
```
